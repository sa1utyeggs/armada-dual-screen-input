# 下屏 FT5452 读取方式对照

这项单独授权、单独许可的实验只改变现有下屏专用驱动的寄存器读取分组，不进入应用包。原基线驱动及其来源保持不变，见 [UPSTREAM](UPSTREAM) 和 [GPL 许可证](../LICENSE)。

`read-chunks.patch` 应用于 SHA-256 为 `9fdb33c22b2241a13f3a5371e01989b54f39d3fd687865d676ea6cc7875bdaba` 的基线模块源码。仅 root 可操作的 `read_chunk` 参数接受：

| 参数 | 读取方式 |
| --- | --- |
| 1（默认） | 不变的基线逐寄存器读取 |
| 6 | 先读三字节头部，再按每个触点六字节读取 |
| 33 | 一次读取完整的 33 字节帧 |

每帧只取一次参数快照。补丁保留触点解析／坐标／ID、IRQ 设置、电源处理和匹配限制，不增加移动过滤或额外固件配置。这条总线可能不支持成组读取；失败或短事务会使实验作废并触发恢复，不会悄悄改写或丢弃坐标。

按现有构建流程，使用完全匹配且已准备的内核／配置／编译器离线编译，并逐个审计导入符号。生成的源码、二进制、清单、审计、源码哈希和编译器记录均留在应用包之外。编译和只读计划成功，不代表加载安全或硬件行为正确；加载这个新候选需要单独明确授权。

`run_trial.py PACKAGE` 只执行现有组件的兼容性／清单检查并输出计划。实际运行还需 `--run --experimental --folder FRESH_DIRECTORY`。先停止输入面板，使用不发送输入的自有下屏原生窗口；窗口在 `input.json` 中提供新鲜心跳，包括单调时间 `at`、整数 `contacts`，以及按落下顺序排列、数量匹配且互异的正整数 `ids`。两触点持续 0.2 秒后，实验按 `1、6、33、1、33、6、1` 自动切换，默认每档六秒，不要求操作者在切换时改变动作。最先落下的触点必须一直保持；第二指可以抬起再落下，但不能接替第一指身份。第一触点结束、额外触点、状态过期、I2C 事务失败、取消或超时都会中止对照；输出目录中的 `cancel` 文件可请求取消。扩展后的被动追踪还记录总线载荷，采集体积更大；完整对照可能达到 32 MiB 上限并中止，不能把截断的采集当作已完成对照。

运行器复用现有 root 管理组件的精确内核／摘要校验、操作锁和下屏专用控制器，退出时恢复该组件固定的原实验包，包括追踪停止失败的情况。不更新已安装 GUI 组件、不管理官方服务、不创建开机加载；调用者按需保留／恢复自己的输入面板。运行前原实验驱动必须已启用。实际验证范围以包清单和实验日志为准，不能视为修复验收。
