# 下屏定向坐标采集

该 GPL-2.0-only 工具不进入应用包。它打开自有下屏原生 X11 窗口，观察手动触摸，并在不抓占的情况下只读物理 `bottom_touchscreen` evdev 流。不发送输入、不变换记录坐标、不增加移动过滤，也不管理服务、模块、开机文件或控制器寄存器。上层实验的许可与来源记录保留在[驱动目录](../README.zh-CN.md)。

运行前应确认 X 显示 `:2` 仍属于下屏 Gamescope 会话，并单独安排输入面板原有状态的保留／恢复。显示参数故意要求显式指定，当前准备版拒绝其他显示。下屏必须保持开启。使用已存在的全新输出目录和 Thor 已安装的 Python／运行时：

```bash
python3 -B window.py /tmp/fresh-capture-a --display :2 --target A --language zh-CN --trace-required
```

界面语言显式指定，默认英语。窗口只借用已安装应用的下屏会话环境，不导入其手势、定位或输入发送逻辑。`ready` 文件和 `mapped` 日志标明自有窗口；应先核对内容及所在屏幕，再提示操作者触摸。

操作者用第一指按住蓝色圆心。其 GDK 序列成为固定主触点，不能被其他触点接替。随后 `capture-request` 标记允许外部有界被动追踪开始；启动器仅在追踪就绪后写入 `trace-ready`。窗口记录三秒单指基线，再提示第二指落在橙线上并上下滑动十秒。第一指必须始终按住；第二指允许抬起再落下，每次身份均记录。扫描完成或作废时写入 `capture.done`；应把此路径传给追踪器的 `--done`。启动追踪和恢复面板仍由外层启动器负责。追踪应等待标记再开始，不能在等待用户时消耗短采集时长。

可选 `--post-hold-seconds 3` 增加最后一组对照；默认值为 `0`，保留此前 A／B 流程。滑动完成后，窗口提示第一指继续保持、仅抬起第二指，最多等待十秒；随后再记录三秒单触点基线，才提示全部抬手。第二指再次落下或第一指提前抬起都会使此对照作废。`capture.done` 延后至最后基线结束时写入。采集器的 30 秒／32 MiB 上限保持不变，操作者响应过迟可能使采集中止，不会延长上限。

可选 `--scan-mode stationary --post-hold-seconds 3` 用三次定点保持代替连续滑动：橙色上端 `(950,300)` → 下端 `(950,900)` → 再次上端。第二指 GDK 坐标必须位于高亮目标半径 80 个参考坐标单位内持续三秒；离开或抬起会重置本次保持计时。每个位置最多允许六秒到达目标，到达后保留完整三秒保持时间，总时限为九秒。离开目标不会重置原来的移动时限。第一指身份必须始终保持，额外触点会使本轮作废。半径判断仅控制诊断流程；记录的 GDK／物理坐标均不变，不应用移动补偿。三秒末尾单触点对照仍为必需。采集仍受 30 秒／32 MiB 上限约束。阶段和状态记录均保留当前目标序号及坐标，包括重复尝试。

可选 `--continuous-secondary` 进一步要求第二指在三个定点阶段始终保持同一 GDK 身份，直到窗口提示抬起第二指。在移动／保持阶段抬起或被新触点替代都会使本轮作废。窗口明确提示沿橙线滑动、不要抬起。默认关闭此选项，保留此前允许第二指重新落下的流程；非定点模式会拒绝该选项。就绪记录包含该选项和定点阶段的 6／3／9 秒时限，阶段／状态记录保留固定的第二指身份。

`launch_capture.py` 仅提供上述被动追踪联动。在操作者触摸已就绪的窗口之前，用另一个进程启动它：

```bash
sudo python3 -I -B launch_capture.py /tmp/fresh-capture-a
```

目录必须是绝对路径、已经存在，并属于 `SUDO_UID` 标明的非 root 操作者；旧标记／追踪文件或符号链接目录会被拒绝。启动器默认最多等待 `capture-request` 600 秒，然后启动同级被动采集器，保留其 32 MiB 上限，采集最长 30 秒，并给追踪初始化五秒时间。仅在采集器报告初始化成功后写入 `trace-ready`。成功退出还必须确认采集器已移除自己的私有追踪实例，并看到 `capture.done`。失败或提前结束会写入 `trace-failed`，窗口据此显示双语错误说明并使本轮作废。`trace-result.json` 保留有界的采集器输出／错误、退出状态和清理结果。经 sudo 写入的文件归还给 `SUDO_UID`。取消／信号只结束私有采集子进程，先给三秒正常清理时间，必要时再强制结束并最多等待两秒。启动器不管理面板或其他服务，需单独安排并核实面板恢复。任何单次进程等待均不超过五秒。

`window.py` 和 `launch_capture.py` 均接受范围为 1…600 的 `--wait-seconds N`，默认 600。窗口另有独立的 50 秒操作时限，从发出第一份采集请求时开始；等待用户不会消耗此时限，重复请求也不能重置它。在等待截止前已观察到的有效第一指触摸，可以在下一次界面时钟回调处理，仍保留完整操作时限。窗口就绪／状态／请求记录保留这两项时限及截止时间；启动器另行记录自己的等待、30 秒采集和初始化时限。等待第一指超时与开始操作后的超时采用不同的诊断原因。采集器的 30 秒／32 MiB 上限保持不变。

A 轮固定目标为 1240×1080 参考画布中的 `(260,760)`，B 轮为 `(260,540)`。两轮第二指轨道均为 x=950、y=300…900。此前记录显示原始 X 大致映射为原生窗口反向 Y，但应利用新一轮原始／界面记录再次核对。仅改变固定目标的 Y，用于区分异常原始 X 区域是跟随第一触点，还是固定在屏幕某处。A／B 需分别使用全新目录，中间全部抬手。这些目标属于实验控制，不是已验证的通用故障边界。

`window-events.jsonl` 保留未改动的 GDK 坐标／源时间戳、每次 SYN_REPORT 的只读 Type-B 快照及阶段变化。原始源时间戳保留 evdev 已有时钟；每条记录另有主机单调时间 `at`，初始化时记录实时时钟／单调时钟对。触摸前查询初始槽位坐标，触点 ID 更换时仍保留未更新的轴缓存。SYN_DROPPED、物理节点不唯一、额外触点、第一指提前抬起、下屏关闭或超时都会使实验作废，不会悄悄修补缺失数据。`status.json` 提供当前阶段／身份，`done` 标记窗口退出。不修改保存的用户设置。

离线检查覆盖事件缓存语义、身份／阶段保护、中英文键／占位符，以及使用私有模拟子进程进行的采集联动／失败清理。Linux GTK／Pango 绘制、下屏焦点／位置、真实追踪联动和硬件行为仍需设备验证；Mac 单元测试通过不代表这些检查通过。
