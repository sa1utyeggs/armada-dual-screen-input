# 双指滚动后的触点恢复

状态：修复候选，等待实机复测；未替换掌机已安装版本。

## 问题与已确认范围

用户反馈双指滚动一段时间后，指针无法移动，但顶部按钮仍可操作。
纯内存模拟确认：若应用漏收到一根手指的 END/CANCEL，`ToolkitTouch`
会一直为残留序列续期。后续真实单指被当成双指滚动，残留更多时还会触发
多指保护。模拟能重现这一代码路径；本次设备现场已关闭，尚未确认实际遗漏
发生在应用、GTK、合成器还是触屏驱动层。

## 修复方式

- Wayland GTK 将从空触点集合开始的第一根手指标记为 pointer-emulating。
  `PanelApp` 只在真实 `TOUCH_BEGIN` 回调中传递这一标记；`ToolkitTouch`
  收到可信的新组标记时，先取消残留触点并释放本应用持有的输出，再开始新触摸。
  不伪造普通抬手，因此清理不会触发点击。
- 保留 keepalive。普通第二指不清理第一指，也不设置静止超时，避免影响长按、
  拖动、修饰键和一根手指静止的双指滚动。
- 双指变单指时，从剩余手指的当前位置重新计算移动，清除旧滚动的指针余量和
  速度；保留已经建立的指针移动意图、整组触摸的最大手指数和行程，避免回放滚动
  距离、误触点击或惯性。

GTK 标记的依据见[官方 Wayland 后端源码](https://github.com/GNOME/gtk/blob/gtk-3-24/gdk/wayland/gdkdevice-wayland.c#L2317)。
这一恢复依赖 GTK 已识别出新的一组触摸；如果内核或合成器自身仍认为旧手指
没有抬起，可能不会产生新组标记，该层问题仍需实机记录区分。

## 验证与后续复测

自动检查全部使用模拟事件或内存输出，不创建真实输入设备。覆盖丢失 END、
多残留触点、序列复用、普通第二指、长时间静止、无效事件和双指转单指；
Linux 检查还通过真实 `PanelApp._on_touch` 回调验证新组标记的传递。
最终临时副本中，Linux 完整 142 项通过；Mac 123 项通过，19 项 Linux GTK
集成检查按平台跳过。检查未启动真实面板，也未替换掌机安装文件。

用户方便后再用相同应用连续双指滚动、全部抬手后单指移动，并交替使用键鼠页、
双指轻点和长按拖动。需要同时确认恢复能力和原有手感；当前模拟通过不代表
实际设备的偶发故障已经验证解决。
