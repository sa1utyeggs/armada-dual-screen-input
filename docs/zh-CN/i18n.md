# 界面语言

本功能包含在 v0.1.4 中。界面支持 English 与简体中文，和键盘输入语言独立。

## 使用与迁移

在 **设置 → 通用 → 界面语言** 循环选择“跟随系统 / 简体中文 / English”，点击保存后立即应用，不重启面板。

- `~/.config/thor-panel/config.json` 中使用独立字段 `ui_language`，取值 `auto` / `zh_CN` / `en_US`。
- **缺少、损坏或不支持的字段值均回退英文**。不会根据现有中文键盘配置推断界面语言；老配置也遵循此默认值。
- `keyboard_language` 继续控制英文 US / 中文拼音，切换界面不改变输入法、键盘布局、游戏语言或系统语言。
- “跟随系统”在启动和保存时解析应用继承的语言环境：`LC_ALL` 优先于 `LC_MESSAGES` 和 `LANG`；非 C/POSIX 环境下优先参考 `LANGUAGE` 列表。支持中文和英文，其余回退英文。
- 游戏模式处于 C/POSIX locale（包括 Armada 的 `C.UTF-8`）时，启动器在每次启动面板前只读一次 `~/.steam/registry.vdf`，用 Steam 界面语言补充识别。`schinese` / `tchinese` 选择简体中文，`english` 选择英文；缺失、损坏、过大或不支持的值均回退英文。手动界面语言和非 C 系统 locale 继续优先。修改 Steam 语言后需重开面板；运行中保存“跟随系统”使用本次启动取得的值。不写入 Steam、系统 locale 或注册表设置，桌面模式不接收 Steam 语言提示。
- 改动在保存前只存在于草稿；放弃、离开设置或保存失败均保留原界面语言。恢复“通用”默认值仅将界面语言重置为英文，仍需保存。
- 未知个人配置字段、灵敏度、滚轮、圆环帧率/配色、自启动选择与原生输入逻辑保留。
- 桌面入口使用英文默认名称，并提供 `Name[zh_CN]` / `Name[zh]` 及对应说明，由桌面语言环境选择；面板内语言设置不修改桌面会话语言或文件名。

## 实现与后续翻译

`ui_catalogs.py` 保存稳定的消息键和中英文模板。`i18n.py` 不导入 GTK、不改系统 locale，不进行磁盘或网络访问；界面和状态在显示时解析语言。每个状态消息最多缓存两种语言的结果，不按输入事件读取翻译文件。

独立的启动器辅助模块最多读取 64 KiB 注册表，仅读普通文件，并按精确的 Steam 客户端语言路径取值，不读取账号专用或游戏语言配置、不执行 Steam 命令。绘制和输入回调没有增加文件读取或轮询。

按钮、设置、状态栏、触屏说明、拼音后端提示及更新错误均走统一资源。状态模型保留消息身份，功能判断使用状态键，不依赖某种语言的提示前缀。输入的中文候选、原始错误详情、协议/配置字段和按键字符不是待翻译的界面文案。

独立更新任务继续写 schema 1 的普通 `message`，并增加可选 `message_i18n` 元数据；旧读取器仍能读取普通文字，新读取器验证元数据后按当前界面语言显示。历史状态文件或不可用的翻译元数据保留原始提示，不猜测或改写历史错误。完整性校验失败等技术错误中的原始详情可能仍是英文。

Pango 排版语言和文字布局缓存随界面语言区分；触屏静态背景缓存也包含语言，保存时请求完整重绘，避免旧语言残留。没有增加逐帧翻译文件读取、子进程或额外输入事件。

新增文案时同时添加两个语言模板；动态内容使用同名占位符，不拼接句子。安装包白名单包含 Python 翻译资源及本文。界面截图仍可能保留中文作为示例，第一方文档已提供英文默认路径与独立简体中文版本。

## 验证范围

自动检查覆盖默认英文、系统语言解析、翻译键与占位符一致性、状态/错误即时切换、保存/放弃/失败与重载、旧更新状态兼容和离线包资源完整性。Linux 使用真实 Pango/Cairo 离屏绘制中英两种语言的触控板、定位、直接触屏及五个设置页，检查未知字形、单行宽度和最小 16px 字号；缓存检查覆盖语言切换后的重新排版。

这些检查不创建输入设备或真实窗口，不向 Steam 或游戏发送测试输入。尚待安装后的用户交互验收，以及长期运行和休眠恢复验证。安装功能不代表启用了桌面模式或增加了新的输入语言。
