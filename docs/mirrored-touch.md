# 同屏触摸与双指滚轮

状态：基础逻辑已实现，画面与实际输入后端尚未接入；未部署为可用功能。
最后更新：2026-10-19。
目标平台：ArmadaOS 双屏设备，首个实机目标为 AYN Thor 的 Steam Game Mode。

## 使用目标

下屏显示上屏等比例镜像，点按与拖动作用于画面对应位置。
第一轮游戏验收使用《杀戮尖塔2》的选牌、拖牌、选择目标和菜单操作。

| 手势 | 目标效果 |
| --- | --- |
| 单指点按 | 点击上屏对应位置 |
| 单指按住移动 | 保持接触并拖动 |
| 双指上下滑动 | 在双指中点对应位置发送垂直滚轮 |
| 双指左右滑动 | 发送水平滚轮，实际效果由目标应用决定 |
| 暂停、关闭、会话切换 | 停止捕获并释放输入 |

下屏预留暂停触摸、释放触摸、返回键鼠和关闭按钮。
第一版支持单指和双指滚动，局部放大、捏合缩放、多指操作及 Desktop Mode 待后续适配。

## 当前代码

- `mirror_geometry.py`：等比例矩形、工具栏偏移、0/90/180/270 度旋转、源坐标与触点标记的双向变换。
- `mirrored_touch.py`：只产生输入意图的状态机，无硬件或 GUI 依赖，不创建虚拟设备。
- `gamescope_probe.py`：读取明确指定的同用户 Wayland socket，查询接口与捕获节点；不取帧、不发送输入。

现有 `panel_app.py` 尚未调用这些模块，已有键盘和触控板行为保持原样。
测试不等同于镜像显示、游戏输入或长时间性能已通过验收。

## 坐标约定

画面和触摸共用一个 `MirrorTransform`。尺寸由实际捕获源与下屏可用区域提供，不使用固定机型分辨率。
转换结果是捕获源内的归一化坐标，包含捕获画面原有黑边；实际输入后端还必须处理合成器的输出坐标约定。
GTK 已处理的下屏旋转不能再次叠加；`rotation` 仅表示镜像渲染额外施加的旋转。

落在镜像外的新触摸被忽略。已开始的拖动越过画面边缘时，坐标夹紧并继续等待抬手。
几何尺寸变化前必须先取消旧手势，避免拖动突然跳到新的映射位置。

## 手势判定

初始按下预留 60 毫秒双指判定窗口，当前只是可调的原型默认值，需实机评估延迟。
UI 需要通过非阻塞定时器在 `deadline` 调用 `tick()`，不能依赖下一次移动才能触发长按。
快速点按在抬起时产生一次按下/抬起；窗口内的短拖动保留起点、末端移动及松开顺序。

判定窗口内加入第二指，直接进入双指滚动候选，不向游戏发送第一次按下。
双指按中点位移滚动，默认每滑过镜像短边长度产生 3 格滚轮，保留高精度小数量；真实后端需要累积后再转换为设备整数单位。
默认滚动方向沿用现有触控板，可通过 `natural_scroll` 翻转。
滚动起始阈值为 4 个 toolkit allocation 单位，进入滚动时只输出超过阈值的部分，无惯性。

已经提交的单指拖动不会因为第二指加入而松开或变成滚轮。
双指抬起一指后等待全部抬起，剩余手指不会变成点击；第三指会停止当前滚动并等待全部离开。
界面必须将控件触摸与镜像触摸分流，不能把顶部按钮纳入这套手势识别。

取消事件与正常松开分开表示。原生触摸后端应尝试取消；鼠标兼容后端只能释放鼠标键，不能撤销已经开始的游戏操作。
调用 `cancel()` 时还必须取消 toolkit 序列和已安排的定时器。

## 捕获与输入后端的准入条件

捕获、渲染和输入分别实现，捕获等待不得阻塞 GTK 输入线程。画面队列只保留最新帧。
必须先确认捕获源是上屏会话，再接受实际输入；探测到节点并不代表实际捕获成功。
Gamescope PipeWire 协议是私有接口，适配层需要单独管理版本和失败状态。

2026-10-19 在 Thor 上只读探测确认：

- `gamescope-primary` 提供 `gamescope_pipewire` 并通告节点；尚未测试实际帧数据。
- 系统具有 PipeWire、Wayland、EGL 运行库以及 GStreamer 的 `videoconvert`、`appsink`、`glimagesink`。
- 系统 GStreamer 缺少 `pipewiresrc`；后续需验证应用私有运行库或原生 PipeWire 后端。
- 上屏注册表未提供 `zwlr_virtual_pointer_manager_v1`；不能直接按该协议实现绝对鼠标输入。
- `/dev/uinput` 可写，但新增绝对设备的上屏归属、输入循环隔离仍未验证。

第一轮探测曾遇到设备 UFS 恢复失败和数据分区只读，用户重启后恢复可写。
现场保存在 Mac 项目外的诊断目录，未将设备日志提交进仓库；根因仍需单独排查。

正式输入需要额外验证目标会话、前台应用、画面新鲜度和会话代次。
画面停滞、目标变化、Steam 菜单覆盖、休眠或连接断开时，停止发送新动作并释放已有输入。
恢复连接后丢弃旧序列，必须从新的触摸开始。

## 后续里程碑与验收

1. 捕获原型：获得上屏实际帧，在独立预览中验证比例、方向、最新帧策略和延迟。
2. 输入原型：先在测试窗口验证绝对坐标、按下/移动/松开及滚轮，再接入游戏。
3. GTK 整合：新增同屏触摸入口及控制按钮，接入现有释放、收起、关闭和会话生命周期。
4. 游戏验收：选牌、连续拖牌、取消操作、列表滚动及边缘目标无误触。
5. 生命周期与性能：模式切换、休眠恢复、目标退出不残留输入；记录上下屏帧时间与镜像延迟。

镜像显示目标为 60FPS，实际性能和功耗尚未测量；如有必要再评估 30FPS 选项。
每个里程碑都需区分纯逻辑测试、Linux 集成测试与用户游戏体验结果。
