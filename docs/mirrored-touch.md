# 同屏触摸与双指滚轮

状态：功能分支已将实验预览整合到原面板，在 AYN Thor 的 Steam Game Mode 验证；PR 仍为草稿，未合并到 main。
最后更新：2026-10-19。

## 目标与当前使用

下屏显示上屏等比例镜像，点按与拖动作用于对应位置，减少直接触摸上屏的需要。
长期目标是 ArmadaOS 双屏设备；目前仅 AYN Thor 有实机记录，Desktop Mode 尚不开放。

| 手势 / 控件 | 效果 |
| --- | --- |
| 启用触摸 | 原面板进入后自动等待就绪；手动暂停后用此按钮恢复。独立开发预览仍手动启用 |
| 原生触摸（默认） | 直接传递点按 / 滑动，最多两个独立触点；不等待双指、不模拟滚轮 |
| 鼠标兼容 | 单指左键点按 / 拖动，双指模拟垂直 / 水平滚轮 |
| 切换模式 | 释放旧连接；原面板等待就绪并抬手后自动连接，手动暂停时保持暂停；独立预览须重新启用 |
| 释放并暂停 | 释放输入，丢弃旧触摸序列；保留画面预览 |
| 关闭预览 | 停止捕获、释放本程序输入并退出，显示下方原有界面 |

### 原面板中的入口

通过原桌面“虚拟键鼠”快捷方式手动打开，在顶部选择“同屏触摸”。
镜像页沿用 main 的深色样式与只读状态栏；顶部原左 / 右键位置改为“暂停触摸 / 启用触摸”和“原生触摸 / 鼠标兼容”，
“释放按键”在此页改为“释放触点”。切回键鼠页时恢复原按钮含义与键盘位置。
进入后画面与目标有效、焦点持续稳定 200ms、所有已知真实触摸序列结束至少 80ms，才自动连接并启用。
连接途中有新手指落下也继续等待抬起；切换标签时清理逻辑手势不会清除真实手指状态。
默认原生模式，不把双指转换成滚轮。手动“暂停触摸” / “释放触点”会持续暂停，须点“启用触摸”恢复。
切页、收起、隐藏或关闭会立即释放并关闭输入，停止捕获；重新进入 / 展开自动等待就绪。
前台窗口或输入失效时先释放旧序列，目标重新稳定并抬手后自动恢复，旧手指不续接；连接失败至少间隔 1.5 秒重试。
切换原生 / 鼠标方式同样等待就绪并抬手；若先前是手动暂停，则不会自动恢复。
镜像画面仅在该页可见时捕获，快速切页会等待前一管线停止后再开始，避免重复消费者。
最后选择的页签通过原配置中的 `mode` 保存，启用状态与手指不会保存或续接。
Steam 原生键盘抑制只在键鼠页生效，镜像页不抑制。没有启用开机启动或增加第二个快捷方式。

### 独立开发预览

原生模式通过临时 libevdev / uinput 触摸屏送入上屏，与物理上屏触摸经过相同的 Gamescope 策略。
Steam 界面触摸模式为 4（透传），用户已确认单指滑动、点按正常。
《杀戮尖塔2》运行时模式为 1（触摸映射为左键），沿用该设置；用户已确认选牌、拖牌和菜单正常。
这不表示该游戏收到原生多点触摸：工具发送真实触点，应用最终收到什么由现有 Gamescope / Steam 设置决定。
原生模式不创建 EIS 鼠标连接，也不模拟双指滚轮；手势由上屏应用处理。鼠标兼容模式仍使用 EIS。
局部放大、游戏中的多点触摸手势及长期性能尚未验证。

在正常图形用户的开发源码目录内运行，无需 sudo：

```bash
python3 -B mirror_launch.py --x-display :0 \
  --runtime-root /path/to/private/runtime \
  --gtk-runtime-root "$HOME/.local/share/thor-panel/runtime"
```

`:0` 是已核实的 Thor 上屏 Gamescope 控制 XWayland，其他设备需要先确认。
游戏实际使用的 XWayland display 由 Gamescope 焦点属性跟踪，不固定为 `:0`。
`--fps 30` 可作对照，缺省上限为 60。运行库准备见[原型运行库](mirror-runtime.md)。
`--input-mode native` 为默认；可用右上角切换，或传 `--input-mode mouse` 选择鼠标兼容。
独立预览不改 `thor-panel.service`、原配置、快捷方式、官方下屏或游戏设置，没有新增自启动。
上述独立预览仍可放在临时目录；已安装的原面板使用用户持久目录内的代码和私有插件，见[运行库](mirror-runtime.md)。
两种界面复用同一输入与捕获模块，不要同时开启镜像捕获。

原键鼠的按键布局、触控板灵敏度与滚轮缩放保持原样。

## 画面与坐标

当前使用单条原始尺寸管线，源与帧均为实测 1920×1080，Cairo 在下屏按比例绘制，不写死机型分辨率。
此前先读首帧再重连为 960×540 的方案遇到首帧超时；动态协商缩放又触发 PipeWire 缓冲移除错误，已回退。
使用独立缓冲副本，避免下游持有 PipeWire 缓冲池；转换前用 `videorate drop-only=true` 限帧，不生成重复帧。
断开会报错，不静默保留旧流；静止时等待首帧，不再把两秒没有数据直接当失败。
首次尚无图像时保持禁用输入，并提示用手柄切换一次项目，以触发上屏更新。
捕获和源心跳均在工作线程；GTK 只读最新帧，两个有界队列各至多保留一帧。

Gamescope 按画面变化推帧，静止画面可能没有新帧，不能仅凭更新速率低判断故障。
350ms 内的新帧可作近期画面；更旧的静止画面需要同时确认捕获线程响应、同一 socket / 节点存在、
合成器查询有近期响应和输入目标有效。源探测有 800ms 超时，超过 2 秒未确认会失效，GTK 不等待探测。
该检查无法证明响应中的生产者没有内部停帧缺陷，仍需端到端和休眠恢复测试。

显示和触摸共用 `MirrorTransform`。镜像外的新触摸忽略；已开始的拖动越界后夹紧，等待抬手。
GTK 已处理的下屏旋转不重复施加；几何变化会暂停并丢弃旧序列。
Gamescope EIS 通告的 INT32_MAX 区域是占位范围；实际绝对输入使用前台 surface 像素坐标，不能乘以占位范围。
首版使用已核实的前台窗口尺寸，要求窗口与捕获源宽高比一致；不同宽高比、裁切和非默认缩放需实际合成变换后再支持。

## 手势与隔离

**原生模式**立即传递有效落指，独立跟踪两个触点，忽略镜像黑边内的新落指与超出容量的第三指。
移动中的触点越出镜像后夹紧；暂停、切换模式或关闭均释放触点并移除设备。
按用户要求，原生模式不将双指转换成滚轮。

以下 60ms 判定及滚轮规则只适用于**鼠标兼容模式**。初次落指预留 60ms 双指判定窗口，用非阻塞定时器推进。
快速点按在抬起时发送按下 / 松开，短拖动保留起点、末端和松开顺序。
窗口内第二指加入时转为双指滚动，不先点击游戏。
已提交的单指拖动不会因第二指加入变成滚轮；双指操作后等待全部手指离开，第三指会停止滚动。

默认滑过镜像短边相当于 3 格滚轮，起始阈值为 4 个 toolkit 单位，无惯性。
细小位移先累计，达到一格后通过 EIS 离散接口发送 120 的整数倍；不同时发送连续接口，避免重复滚动。
暂停和结束滚动清空小数余量，下一次手势不继承残留。此版本仍待用户实际双指验收。
参数独立于原触控板的 `scroll_speed` / `scroll_scale`。
顶部控件、状态栏与镜像内容区域分开，不进入游戏手势状态机。
集成页的绘制与触摸共享 1240×1080 逻辑坐标，镜像不使用原 UI 的轨道微移，以免图像与绝对触点错位。
鼠标兼容只能释放按钮；原生模式的释放也是抬起，无法撤销已发生的动作，不是真正的 touch cancel。

现有鼠标镜像只连接明确指定的上屏 EIS，不创建新 uinput，不读或独占物理 evdev。
通过 Unix peer credentials 核实 XWayland 与 EIS 属于同用户的同一个 Gamescope。
原生模式按需创建自己的临时触摸设备，后台每 250ms 核对只有同一上屏 Gamescope 打开它；
检查超过 750ms 未更新或节点身份变化则停止输入。不会读取或独占物理 evdev，不修改 udev / Steam 触摸属性。
目前沿用应用已有的模式 1 / 4；其他触摸模式会拒绝启用，用户可选择鼠标兼容。
跟踪 socket 代次与焦点快照；窗口、尺寸、输入焦点变化，或覆盖层使输入 / 图形 app 不同，会暂停。
原面板就绪并抬手后自动恢复，手动暂停除外；独立预览仍须重新启用，旧手指均不会续接。
下屏 layer-shell 键盘焦点模式为 NONE；不改光标、亮度或系统输入配置。

### 拖动连续性与焦点判断

自动启用后用户反馈偶发停住、断开或跳动。诊断日志记录了目标 / 焦点变化引发的中断，
其中有一条发生在触点尚未抬起时；首轮日志只有“快照不同”，没有旧 / 新字段差异，不能确认全部中断的具体来源。
代码检查发现旧判断把子控件的 XID 也作为整个目标身份；Steam / Chromium 在同一窗口内部切换控件时会改变该值。

现在仅当祖先检查证明新子控件仍属于同一个可见上屏窗口，且应用、图形应用、尺寸、Gamescope 进程、
XWayland display 和触屏策略均不变时，保持同一个输入连接和触摸序列。
真正换窗口 / 应用、失焦、尺寸变化、覆盖层或触屏模式变化仍立即释放；没有延长超时或增加拖动判定延迟。
自动启用的目标稳定判定使用相同的目标定义，避免子控件切换反复重置等待时间。

保留仅在输入中断时输出的 `[mirror]` 状态日志：失败原因、帧 / 捕获 / 焦点时间年龄、变化字段名和聚合发送数。
不记录触点坐标、接触 ID、画面、窗口标题或输入文字；诊断数据不提交仓库。

## 实测与限制

2026-10-19，AYN Thor / Armada `20261010.c3d178c`：

- Mac 和 Thor 各 104 项镜像 / 原生触摸相关测试通过；实机 GUI 和用户交互验收另行记录。
- 专用上屏窗口通过绝对坐标、左键按下 / 拖动 / 松开和上下左右滚轮检查；目标不在前台时拒绝发送按钮。
- 历史缩放管线曾在 7 秒记录 408 帧；当前原始尺寸管线三次后台检查各约 4 秒，分别记录 232、237、237 帧，均无错误且正常停止。不能据此认定游戏性能通过。
- GTK 下屏逻辑布局为 689×542，状态中文缺字数为 0；方向、比例和按钮经过布局检查。
- **用户已确认：镜像正常，点按和拖动可作用到上屏。** 未细分是 Steam 还是具体游戏，不能写成《杀戮尖塔2》专项通过。
- 后续原生模式接入后，用户明确确认 Steam 单指滑动 / 点按正常，以及《杀戮尖塔2》选牌、拖牌和菜单正常。
  最终直接触摸版本一轮约 249 秒，最后一次启用累计 57 次按下、525 次移动、57 次抬起、0 次滚轮。
  开发者结束预览后捕获状态 `stopped`、无捕获错误、进程退出，临时触摸设备为零；Steam 游戏继续运行。
- 用户反馈暂停和关闭正常；开发中曾有两次隐藏窗口后进程未退出，只回收测试进程，未重启 Steam。
  改用显式 GLib 主循环和一次性退出回调后，原始尺寸管线两轮实际触摸后正常停止，日志走到 `closed`，进程已退出。
  其中一轮约 773 秒，另一轮约 266 秒；不能据此认定休眠或长时间稳定性已通过。
- 历史 CPU 缩放 / Cairo 方案有明显开销：一轮 5.05 秒预览用了约 6.13 CPU 秒，约占 1.21 个逻辑核心。当前原始尺寸路径需重新测量。
  对上屏游戏帧时间、功耗和温度的影响尚未量化，不能称为低开销最终实现。
- 当前直接原生触摸的一轮约 249.3 秒用了约 262.5 CPU 秒，约 1.05 个逻辑核心。
  这是活跃镜像场景的进程开销记录，未做关闭 / 开启的游戏帧时间对照，不据此认定游戏性能通过。
- 集成到更新后的 main 后，掌机 247 项 Python 测试全部通过；Mac 运行时 Linux GTK 项跳过，Steam 键盘 JavaScript 另有 15 项通过。
  无上屏触点的界面检查覆盖首帧、初始暂停、原生输入路由就绪、收起停止捕获、展开暂停、返回键鼠和关闭。
  中文缺字为零，检查前后个人配置字节一致。之后用户确认集成页签的镜像、触摸及切回键鼠均正常。
- 按用户要求增加进入 / 展开后自动启用；掌机 256 项 Python 测试全部通过，Mac 230 项通过、26 项 Linux GTK 项跳过。
  实机无触点检查确认按住时不连接，抬手约 0.41 秒后自动启用，手动暂停不自行恢复，恢复按钮与展开自动启用正常。
  收起 / 离页 / 退出均回收设备，未向上屏发送触点，个人配置字节保持不变。
- 拖动连续性修正后，掌机 260 项 Python 检查通过；Mac 234 项通过、26 项 Linux GTK 检查跳过。
  测试覆盖同一窗口子控件切换不中断原生拖动，以及真实目标、失焦和策略变化仍拒绝输入。
  用户复测约 20 秒拖动并点按 / 切换控件，反馈无停住或跳动，同轮日志未见输入中断。
  修正前的诊断版复测也曾正常，因此本轮结果不证明所有偶发卡顿已根治，长期稳定性仍待观察。

双指滚轮修复记录：离散接口拒绝小整数位移，曾改为连续接口，专用窗口能收到 0.1 格滚动。
加入隐藏指针唤醒后，用户仍反馈 Steam 不滚动；状态计数确认已识别双指、发送大量细小滚动请求。
随后在 Steam 游戏库用整格事件做对照，前后镜像确认列表位置会变化；当前改为累计整格发送的候选修复，尚待实际双指确认。
唤醒为相反方向的相对移动，随后绝对定位到双指中点，不改变最终位置；不修改系统指针设置。
界面显示实际发送的整格数；开发模式 `--proof` 可用 SIGUSR2 保存当前窗口及聚合计数，不另接第二个捕获客户端。
聚合计数不包含坐标或文字内容；截图仅在显式启用开发证明路径时保存，不提交用户画面。

未验证：鼠标兼容模式双指滚轮最终效果、原生多点手势的应用效果、长时间游戏、真正 Wayland 原生游戏、不同宽高比 / 裁切、其他机型、Desktop、
休眠恢复、双屏模拟器接管下屏、故障断开时合成器输入状态的恢复。PR 继续保持草稿。
首轮还遇到过 UFS 恢复失败和数据分区只读，用户重启后恢复；证据在项目外，存储问题未被本应用修复。

## 原生触摸与当前兼容方案的区别

最初鼠标原型的单指滑动是左键拖动，未能完整复现 Steam 的触屏体验。
已加入独立的原生触摸模式，直接把触点送入上屏输入路径，并获得用户单指操作验证。

只读核实 Thor 上屏 Gamescope 带有 `--default-touch-mode 4`（Passthrough），并忽略物理下屏触屏。
上屏原有触摸路径与应用开放的 EIS 注入路径是两件事：当前上游 EIS 未通告触摸能力，触摸事件分支也未实现。
这解释了原型选择鼠标兼容路径的原因，但不代表设备不能实现真正触摸转发。

采用只进入上屏的临时虚拟触屏，保留输入目标与画面检查；不需要部署 Gamescope 补丁。
原生触摸模式由 Steam / 游戏及其现有触屏映射识别动作；不支持时仍可选鼠标兼容。
双指滚轮只存在于鼠标兼容模式，同一序列不会同时作为原生触摸和滚轮发送。
已完成临时虚拟触屏的专用窗口路由验证：真正的触摸进入上屏、下屏计数为零、退出后设备移除。
过程和坐标差异见[原生触摸路由验证](native-touch-routing.md)。已接入独立预览与原面板的同屏触摸页；通用安装器仍待完善。
