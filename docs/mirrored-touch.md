# 同屏触摸与双指滚轮

状态：独立实验预览已在 AYN Thor 的 Steam Game Mode 运行；未替换已安装面板，未合并到 main。
最后更新：2026-10-19。

## 目标与当前使用

下屏显示上屏等比例镜像，点按与拖动作用于对应位置，减少直接触摸上屏的需要。
长期目标是 ArmadaOS 双屏设备；目前仅 AYN Thor 有实机记录，Desktop Mode 尚不开放。

| 手势 / 控件 | 效果 |
| --- | --- |
| 启用触摸 | 对当前上屏前台窗口建立输入连接；初始不会自动启用 |
| 单指点按 | 对应位置的鼠标左键点击 |
| 单指按住移动 | 保持左键并拖动 |
| 双指同时上下 / 左右滑动 | 在双指中点位置发送垂直 / 水平滚轮 |
| 释放并暂停 | 释放输入，丢弃旧触摸序列；保留画面预览 |
| 关闭预览 | 停止捕获、释放本程序输入并退出，显示下方原有界面 |

这是鼠标兼容方案。当前 Gamescope EIS 没有原生触摸能力，第一版支持单指点击 / 拖动与双指滚轮；
捏合缩放、真正多点触控、局部放大留待后续适配。
《杀戮尖塔2》的选牌、拖牌、选择目标和菜单是目标验收场景，尚未完成专项游戏验收。

在正常图形用户的开发源码目录内运行，无需 sudo：

```bash
python3 -B mirror_launch.py --x-display :0 \
  --runtime-root /path/to/private/runtime \
  --gtk-runtime-root "$HOME/.local/share/thor-panel/runtime"
```

`:0` 是已核实的 Thor 上屏 Gamescope 控制 XWayland，其他设备需要先确认。
游戏实际使用的 XWayland display 由 Gamescope 焦点属性跟踪，不固定为 `:0`。
`--fps 30` 可作对照，缺省上限为 60。运行库准备见[原型运行库](mirror-runtime.md)。
独立预览不改 `thor-panel.service`、原配置、快捷方式、官方下屏或游戏设置，没有新增自启动。
本轮只部署在临时开发目录，重启后不保证保留；尚无持久安装器或原面板模式入口。

## 画面与坐标

当前使用单条原始尺寸管线，源与帧均为实测 1920×1080，Cairo 在下屏按比例绘制，不写死机型分辨率。
此前先读首帧再重连为 960×540 的方案遇到首帧超时；动态协商缩放又触发 PipeWire 缓冲移除错误，已回退。
使用独立缓冲副本，避免下游持有 PipeWire 缓冲池；转换前用 `videorate drop-only=true` 限帧，不生成重复帧。
断开会报错，不静默保留旧流；静止时等待首帧，不再把两秒没有数据直接当失败。
首次尚无图像时保持禁用输入，并提示用手柄切换一次项目，以触发上屏更新。
捕获和源心跳均在工作线程；GTK 只读最新帧，两个有界队列各至多保留一帧。

Gamescope 按画面变化推帧，静止画面可能没有新帧，不能仅凭更新速率低判断故障。
350ms 内的新帧可作近期画面；更旧的静止画面需要同时确认捕获线程响应、同一 socket / 节点存在、
合成器查询有近期响应和输入目标有效。源探测有 800ms 超时，超过 2 秒未确认会失效，GTK 不等待探测。
该检查无法证明响应中的生产者没有内部停帧缺陷，仍需端到端和休眠恢复测试。

显示和触摸共用 `MirrorTransform`。镜像外的新触摸忽略；已开始的拖动越界后夹紧，等待抬手。
GTK 已处理的下屏旋转不重复施加；几何变化会暂停并丢弃旧序列。
Gamescope EIS 通告的 INT32_MAX 区域是占位范围；实际绝对输入使用前台 surface 像素坐标，不能乘以占位范围。
首版使用已核实的前台窗口尺寸，要求窗口与捕获源宽高比一致；不同宽高比、裁切和非默认缩放需实际合成变换后再支持。

## 手势与隔离

初次落指预留 60ms 双指判定窗口，用非阻塞定时器推进。
快速点按在抬起时发送按下 / 松开，短拖动保留起点、末端和松开顺序。
窗口内第二指加入时转为双指滚动，不先点击游戏。
已提交的单指拖动不会因第二指加入变成滚轮；双指操作后等待全部手指离开，第三指会停止滚动。

默认滑过镜像短边相当于 3 格滚轮，起始阈值为 4 个 toolkit 单位，无惯性。
细小位移先累计，达到一格后通过 EIS 离散接口发送 120 的整数倍；不同时发送连续接口，避免重复滚动。
暂停和结束滚动清空小数余量，下一次手势不继承残留。此版本仍待用户实际双指验收。
参数独立于原触控板的 `scroll_speed` / `scroll_scale`。
顶部 GTK 按钮与镜像画布分开，不进入游戏手势状态机。
取消只能释放鼠标按钮，无法撤销已发生的游戏动作。

现有鼠标镜像只连接明确指定的上屏 EIS，不创建新 uinput，不读或独占物理 evdev。
通过 Unix peer credentials 核实 XWayland 与 EIS 属于同用户的同一个 Gamescope。
跟踪 socket 代次与焦点快照；窗口、尺寸、输入焦点变化，或覆盖层使输入 / 图形 app 不同，会暂停。
恢复后须重新启用，旧手指不会续接。下屏 layer-shell 键盘焦点模式为 NONE；不改光标、亮度或系统输入配置。

## 实测与限制

2026-10-19，AYN Thor / Armada `20261010.c3d178c`：

- Mac 发现 183 项测试，176 项通过、7 项 Linux GUI 检查跳过；Thor 的 76 项新功能相关测试通过。
- 专用上屏窗口通过绝对坐标、左键按下 / 拖动 / 松开和上下左右滚轮检查；目标不在前台时拒绝发送按钮。
- 历史缩放管线曾在 7 秒记录 408 帧；当前原始尺寸管线三次后台检查各约 4 秒，分别记录 232、237、237 帧，均无错误且正常停止。不能据此认定游戏性能通过。
- GTK 下屏逻辑布局为 689×542，状态中文缺字数为 0；方向、比例和按钮经过布局检查。
- **用户已确认：镜像正常，点按和拖动可作用到上屏。** 未细分是 Steam 还是具体游戏，不能写成《杀戮尖塔2》专项通过。
- 用户反馈暂停和关闭正常；开发中曾有两次隐藏窗口后进程未退出，只回收测试进程，未重启 Steam。
  改用显式 GLib 主循环和一次性退出回调后，原始尺寸管线两轮实际触摸后正常停止，日志走到 `closed`，进程已退出。
  其中一轮约 773 秒，另一轮约 266 秒；不能据此认定休眠或长时间稳定性已通过。
- 历史 CPU 缩放 / Cairo 方案有明显开销：一轮 5.05 秒预览用了约 6.13 CPU 秒，约占 1.21 个逻辑核心。当前原始尺寸路径需重新测量。
  对上屏游戏帧时间、功耗和温度的影响尚未量化，不能称为低开销最终实现。

双指滚轮修复记录：离散接口拒绝小整数位移，曾改为连续接口，专用窗口能收到 0.1 格滚动。
加入隐藏指针唤醒后，用户仍反馈 Steam 不滚动；状态计数确认已识别双指、发送大量细小滚动请求。
随后在 Steam 游戏库用整格事件做对照，前后镜像确认列表位置会变化；当前改为累计整格发送的候选修复，尚待实际双指确认。
唤醒为相反方向的相对移动，随后绝对定位到双指中点，不改变最终位置；不修改系统指针设置。
界面显示实际发送的整格数；开发模式 `--proof` 可用 SIGUSR2 保存当前窗口及聚合计数，不另接第二个捕获客户端。
聚合计数不包含坐标或文字内容；截图仅在显式启用开发证明路径时保存，不提交用户画面。

未验证：Steam 双指滚轮最终效果、滚轮手感、长时间游戏、真正 Wayland 原生游戏、不同宽高比 / 裁切、其他机型、Desktop、
休眠恢复、双屏模拟器接管下屏、故障断开时合成器输入状态的恢复。PR 继续保持草稿。
首轮还遇到过 UFS 恢复失败和数据分区只读，用户重启后恢复；证据在项目外，存储问题未被本应用修复。

## 原生触摸与当前兼容方案的区别

用户希望获得 Steam 本身的单指滑动体验。当前原型把触摸转成鼠标，单指滑动是左键拖动，
不能称为原生触摸转发，也不能保证 Steam 会将其识别为手指滚动。

只读核实 Thor 上屏 Gamescope 带有 `--default-touch-mode 4`（Passthrough），并忽略物理下屏触屏。
上屏原有触摸路径与应用开放的 EIS 注入路径是两件事：当前上游 EIS 未通告触摸能力，触摸事件分支也未实现。
这解释了原型选择鼠标兼容路径的原因，但不代表设备不能实现真正触摸转发。

后续需验证能够限定在上屏的虚拟触屏，或扩展 Gamescope EIS 触摸支持，发送接触点按下 / 移动 / 抬起 / 取消。
虚拟设备必须避免被下屏再次接收、避免反馈循环，并正确处理旋转、输出缩放和退出释放。
原生触摸模式由 Steam / 游戏识别单指动作；不支持触摸的应用仍可选鼠标兼容模式。
双指模拟滚轮属于应用手势，需要明确仲裁，不能将同一双指序列同时交给原生触摸和滚轮。
已完成临时虚拟触屏的专用窗口路由验证：真正的触摸进入上屏、下屏计数为零、退出后设备移除。
过程和坐标差异见[原生触摸路由验证](native-touch-routing.md)。尚未接入镜像、修改系统路由或部署 Gamescope 补丁，不能写成原生触摸模式已完成。
