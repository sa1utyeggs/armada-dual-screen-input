# Interface language

Available in v0.1.4. English and Simplified Chinese UI languages are independent of keyboard input.

Open **Settings → General → Interface language**, choose **System language / 简体中文 / English**, then **Save settings**. Missing or invalid `ui_language` defaults to **English**, including older configurations. Input language stays unchanged. Desktop-entry labels independently follow the desktop locale.

<a id="使用与迁移"></a>

## Usage and migration

Cycle through System language / Simplified Chinese / English under Settings → General → Interface language. Save applies the selection immediately, without restarting the panel.

- The independent `ui_language` field in `~/.config/thor-panel/config.json` accepts `auto` / `zh_CN` / `en_US`.
- **Missing, malformed and unsupported values all fall back to English.** Chinese keyboard preferences do not imply a Chinese UI; older configurations follow the same default.
- `keyboard_language` still selects English US / Chinese pinyin. UI changes do not alter input methods, keyboard layouts, game language or system language.
- System language resolves the app's inherited environment at startup and on save: `LC_ALL` takes precedence over `LC_MESSAGES` and `LANG`. In non-C/POSIX environments, `LANGUAGE` preferences are considered first. Chinese and English are supported; other languages fall back to English.
- Edits remain in the draft until saved. Discarding, leaving settings or a failed save keeps the old UI language. General-page defaults reset only UI language to English, and still require Save.
- Unknown preferences, sensitivity, scrolling, ring frame rate/colors, autostart choice and native input behavior are preserved.
- The desktop entry has an English default name plus `Name[zh_CN]` / `Name[zh]` and matching descriptions. The desktop selects these labels; the app's language preference changes neither desktop-session language nor filenames.

<a id="实现与后续翻译"></a>

## Implementation and future translations

`ui_catalogs.py` contains stable message keys and English/Chinese templates. `i18n.py` imports no GTK, changes no system locale and performs no disk or network I/O. UI text and status messages resolve their language when displayed. Each status message caches at most two language results; input events never read translation files.

Buttons, settings, the status row, touch instructions, pinyin-backend messages and update errors share the same resources. Models retain message identity, and behavior uses state keys instead of a language-specific message prefix. Chinese candidates, raw error details, protocol/configuration fields and key characters are content rather than translatable UI labels.

The detached updater keeps its schema-1 plain `message` and adds optional `message_i18n` metadata. Old readers still read plain text; new readers validate the metadata and display the current UI language. Historical files and unavailable metadata retain their original message, without guessing or rewriting an old error. Raw technical details, such as integrity-check failures, may remain English.

Pango language and text-layout caches distinguish UI language. The touch-page static cache includes language too, and saving requests a complete repaint so old-language pixels do not remain. No per-frame translation-file reads, extra subprocesses or input events were added.

Add both templates for new text, use matching named placeholders and avoid joining sentence fragments. The installation whitelist includes the Python catalogs and this guide. Screenshots may retain Chinese UI examples; the documentation now has separate English and Chinese editions.

## Validation scope

Automated checks cover default English, environment resolution, matching keys/placeholders, live status/error translation, save/discard/failure/reload, old updater-status compatibility and offline resource inclusion. Linux checks use real Pango/Cairo offscreen rendering for both languages across the touchpad, position, direct-touch and five settings pages, checking missing glyphs, single-line widths and a minimum 16px font. Cache checks verify relayout after language changes.

These checks create no input devices or real windows and send no test input to Steam or games. Installed interactive acceptance, long sessions and suspend/resume remain pending. Installing this feature enables neither Desktop Mode nor additional input languages.

Initial local validation on 2026-10-22: 211 message keys had matching templates and placeholders. All 563 Python checks passed on Thor. On Mac, 99 Linux checks were skipped and the rest passed; 15 JavaScript checks passed. Sixteen offscreen previews were generated and inspected using Thor's actual fonts. Tests used temporary source directories, without replacing the installed app or changing real personal configuration.

After adding the General-page uninstall action the same day, the catalogs contained 230 matching message keys. All 580 Python checks passed on Thor. On Mac, 102 Linux checks were skipped and the remainder passed, along with 15 JavaScript checks. Bilingual offscreen checks covered uninstall confirmation, busy and error states, for 24 pages in total. Removal was tested only in temporary user directories; Thor's actual installation was neither uninstalled nor replaced.
